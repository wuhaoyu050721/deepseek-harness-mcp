# 0.3.2 验证范围

验证日期：2026-10-10。Windows、Python 3.14.7、MCP 2.3.0、Harness SDK 0.1.5rc1、桌面 runtime 0.2.0-rc.2、Codex 0.162.0-alpha.17.2。

本次完整回归 **566 项测试和 27 个子测试通过**，JUnit 593 项，失败、错误、跳过均为0。新增共享连接、私有登记、双向认证、并行执行、会话幂等、固定项目权限、历史隔离和精确作业清理测试。原直接模式保持四工具，共享模式增加三个会话工具。

实际 Windows 验收同时保持两个官方 MCP SDK 连接，以及两个已安装 Codex 的独立控制上下文。两个 Codex 使用不同项目目录，均发现七个工具；关闭第一个后第二个仍可调用。共享后台由隐藏 WMI 进程启动，前端所在 kill-on-close Job 的整棵树被结束后，后台仍保持相同归属并可调用。最后连接关闭、无待办工作后，后台30秒空闲退出已实际确认。

真实 DeepSeek 桌面调用使用两个独立人工项目：两个审查作业同时处于 running 并成功结束，然后向其中一个会话追问，第三个作业成功恢复其自身历史。项目、标记、历史和工作目录没有串入另一会话，原人工源文件未改变，三个作业的执行树均确认停止，专用 home 清理完成。跨前端使用原请求编号恢复后，没有增加作业或模型执行。没有对业务项目发起模型审核。

首轮验收脚本在关闭 SDK 连接时触发 AnyIO 跨任务上下文错误；模型和工作体断言已完成。修正探针进入/退出上下文的方式后，使用原任务编号恢复并完成关闭及空闲退出验收，没有重复模型请求。这一探针错误不作为服务通过证据，后续修正探针以退出码0和持久化任务核对作为最终记录。

并行执行容量、全局FIFO等待队列、同一会话仅一轮待办、取消一个子代理不影响另一个、停止/清理未确认时保留锁并禁止新执行，以及重启不重放旧任务，使用确定性执行器和真实快照准备回归。真实模型的活动取消、服务商计费停止、Claude共享模式、其他操作系统/Python版本、实际Docker并行运行和当前桌面GUI热加载仍未验收。

源码 ZIP 在没有根 `.git` 的新目录中解压，创建全新虚拟环境并用锁文件离线安装缓存依赖；初始化、桌面前置检查和共享模式七工具握手均通过，只授权人工 sample，未调用模型且未修改个人客户端配置。最终运行模块与该候选包逐字节一致。

完整机器摘要见 [validation-v0.3.2.json](../artifacts/public/validation-v0.3.2.json)。它只包含检查状态、版本与源码摘要，不发布个人路径、配置、对话内容、作业编号或凭证。历史0.3.1验收保留在下文，不能替代新增共享/会话功能的证据。
